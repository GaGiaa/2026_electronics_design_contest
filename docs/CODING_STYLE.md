# C 代码注释与接口文档规范

## 适用范围

本文档适用于仓库内的嵌入式 C 代码，尤其是 `mspm0g3507_app` 中的应用、驱动、算法、协议、服务和平台代码。

说明性正文使用中文。代码标识符、宏名、函数名、命令、路径、协议名称、芯片型号和工具名称保持原样。Doxygen 标签使用标准英文形式，标签后的说明使用中文。

注释的目标是说明接口契约、数据含义、边界条件和设计原因，不是逐行翻译代码。

## 注释位置

### 公共接口

公共函数、结构体、枚举、宏和全局变量的完整说明写在规范头文件中。调用者只阅读头文件时，应能够了解：

- 功能和输入输出含义；
- 参数方向、单位和有效范围；
- 返回值和错误行为；
- 初始化要求和调用前置条件；
- 状态变化、阻塞行为、线程安全和硬件副作用。

根目录兼容头文件只包含规范目录中的头文件，不重复添加注释、声明或实现。规范注释维护在规范头文件中。

### 私有实现

私有函数和源文件中的实现细节使用简短的 `/* ... */` 注释。只解释不容易从代码本身看出的内容，例如：

- 环形缓冲区覆盖最早样本的原因；
- 先放大再除法以保留定点精度的原因；
- 使用 `int64_t` 进行中间计算的溢出保护；
- 中断、任务和共享快照之间的同步约束。

不为显而易见的赋值、递增、条件判断和函数调用添加重复注释。

## 公共函数格式

公共函数推荐使用以下结构：

```c
/**
 * @brief 用一句话说明函数的主要功能。
 *
 * 说明关键处理流程、状态变化和特殊行为。
 *
 * @param[in] input
 *     输入参数的含义、单位和有效范围。
 * @param[out] output
 *     输出参数的内容和有效条件。
 * @param[in,out] state
 *     既作为输入又会被更新的状态对象。
 *
 * @return 返回值的含义、单位和错误行为。
 *
 * @pre 调用函数前必须满足的条件。
 * @post 函数返回后能够保证的状态。
 * @note 需要调用者特别注意的行为。
 */
```

并非每个函数都必须填写全部标签。没有对应内容时不要添加空标签。函数注释应优先说明稳定的接口行为，避免描述容易过期的实现细节。

## 数据、单位和定点数

### 单位

所有物理量和计数都应明确单位。推荐在注释、字段名或宏名中体现：

- 时间使用 `ms`、`us` 或 `s`；
- 速度使用 `mm/s`；
- 角度使用 `deg`；
- 角速度使用 `dps`；
- 编码器增量明确为 `counts/采样周期`；
- PWM 输出明确为百分比或脉宽微秒。

### 定点数

定点数必须说明小数位数、缩放因子和换算关系。例如 `Q8` 应明确说明实际值等于整数值除以 `256`，并说明整数除法的舍入或截断行为。

### 状态对象

状态结构体的注释应说明：

- 是否必须先调用初始化函数；
- 哪些字段由调用者设置；
- 哪些字段由模块内部维护；
- 是否允许多个调用者共享；
- 是否允许在中断上下文中访问。

## 算法注释

算法模块应保持平台无关，不直接依赖 `ti_msp_dl_config.h`。公共算法接口应说明：

- 输入数据的单位、坐标系、符号约定和有效范围；
- 状态初始化方式；
- 每次更新的时间间隔要求；
- 输出结果的单位和边界行为；
- 输入无效、丢线、超时或样本不足时的处理方式。

算法实现注释应说明设计原因和不变量，不重复描述每一行数学运算。

## 驱动注释

驱动接口应说明：

- 使用的外设、引脚、时钟和电气条件；
- 初始化顺序和重试行为；
- 函数是否可能阻塞以及最长等待范围；
- 是否只能在任务上下文或中断上下文调用；
- 读写操作对硬件状态的副作用；
- 错误码、超时和设备不存在时的行为。

驱动不应在注释中混入应用层策略。应用任务的创建、周期调度和功能开关说明属于 `app/` 层。

## FreeRTOS 任务与中断

任务注释至少说明任务周期、优先级用途、栈和队列的所有权，以及是否会阻塞。涉及共享数据时说明快照发布、序列号、临界区或其他同步方式。

中断服务函数注释至少说明触发源、清除标志的方式、可调用的 FreeRTOS API 类型，以及是否向队列发送事件。中断中不得调用可能阻塞的接口。

## 项目文档写作

项目文档的说明性正文使用中文。`FreeRTOS`、`SysConfig`、`CRSF`、`BMI160`、`WS2812`、
函数名、宏名、命令、路径、芯片型号、协议名称和构建输出文件名保持原样，不翻译或改写。

文档之间使用相对 Markdown 链接，并以链接目标文件所在位置计算路径。代码示例统一使用
标准 ````` 围栏；代码围栏必须成对出现，语言标记使用 `c`、`powershell` 或 `text` 等
实际语言。工程 README 只说明本工程职责，不复制依赖版本表和完整 AI 交接状态。

## 配置、验证和维护

功能开关、默认值和互斥关系应在配置头文件或应用 profile 中说明。构建参数只能作为临时覆盖时，应说明它不会修改源码默认值。

注释必须随着接口或行为变化同步更新。不要保留与当前实现不一致的旧说明，不要用注释掩盖未完成的功能。

构建、链接、主机测试和静态检查通过，只能说明对应的软件验证完成，不能替代 Flash、示波器、传感器、电机或其他实物验收。

## 示例：编码器速度滑动滤波器

在 `mspm0g3507_app/algorithms/encoder/encoder_speed_filter.h` 中，公共接口可以这样说明：

```c
/**
 * @brief 更新编码器速度滑动窗口，并返回 Q8 定点格式的平均增量计数。
 *
 * 将本次采样的增量计数加入滑动窗口。窗口未填满时，使用当前已有样本
 * 求平均值；窗口填满后，覆盖最早加入的样本。
 *
 * @param[in,out] filter
 *     编码器速度滤波器状态。调用本函数前必须先调用
 *     encoder_speed_filter_init() 初始化。
 * @param[in] delta_counts
 *     当前采样周期内的编码器增量计数，可以为负数。
 *
 * @return Q8 定点格式的平均增量计数。实际平均值等于返回值除以
 *     (1 << ENCODER_SPEED_FILTER_FRACTIONAL_BITS)。当 filter 为 NULL 时返回 0。
 *
 * @note 返回结果采用整数除法，负数结果向 0 截断。
 */
int32_t encoder_speed_filter_update(encoder_speed_filter_t *filter,
                                    int32_t delta_counts);
```

源文件中只保留算法关键点说明：

```c
/* 窗口未填满时追加样本；窗口填满后覆盖最早的样本。 */

/* 先放大再求平均，保留 Q8 小数精度，并避免 int32_t 中间结果溢出。 */
```

这个示例不要求每个函数都使用完全相同的文字，而是要求每个接口都覆盖实际需要的契约信息。
